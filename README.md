## 🛡️ About the Project

This project investigates the security of network communication generated by **DVWA (Damn Vulnerable Web Application)** using **Wireshark** in a controlled lab environment.

The objective was to capture and inspect network packets, understand how common protocols behave, and identify security weaknesses caused by insecure communication.

The analysis focuses particularly on:

> 🔑 Plaintext credential exposure  
> 🍪 Session-token exposure  
> 🌐 Unencrypted HTTP communication  
> 🔄 Replay-related security risks  
> 📡 Network protocol analysis  
> 📂 Hidden directory discovery

---

## 🎯 Objectives

The project was designed to provide practical experience with both **network analysis** and **web application security**.

The main objectives were to:

- Capture live network traffic using Wireshark
- Inspect HTTP requests and responses
- Analyze common networking protocols
- Examine the TCP connection process
- Identify credentials transmitted without encryption
- Inspect exposed session information
- Investigate session hijacking risks
- Demonstrate replay-related vulnerabilities
- Discover hidden web directories using Gobuster

## 📡 Network Traffic Analysis

### 01 — HTTP Traffic Inspection

HTTP requests and responses generated by the vulnerable application were captured and inspected using Wireshark.

Because the communication was not protected by HTTPS, sensitive information transmitted through HTTP could be observed during packet analysis.

---

### 02 — TCP Analysis

The project examined TCP communication and the connection establishment process.

This included analyzing the TCP handshake and understanding how packets are exchanged between the client and server.

```text
Client                         Server

   │ -------- SYN -----------> │
   │                           │
   │ <----- SYN + ACK -------- │
   │                           │
   │ -------- ACK -----------> │
   │                           │
   │     Connection Ready      │
```

## 🔑 Plaintext Credential Exposure

One of the main security findings was the transmission of credentials through **unencrypted HTTP communication**.

Without transport encryption, sensitive information contained in network traffic may be visible during packet inspection.

```text
User Login
     ↓
HTTP Request
     ↓
Unencrypted Network Traffic
     ↓
Wireshark Capture
     ↓
Sensitive Data Exposure
```

### Security Risk

An attacker capable of observing the network traffic could potentially obtain sensitive authentication information.

### Recommended Mitigation

Use **HTTPS with TLS encryption** so sensitive communication is encrypted while traveling between the client and server.

---

## 🍪 Session Security Analysis

The captured traffic was also inspected for session information.

Exposed session tokens can create a **session hijacking risk** when transmitted through insecure communication channels.

```text
Authenticated Session
        ↓
Session Token
        ↓
Unencrypted HTTP
        ↓
Token Exposure
        ↓
Potential Session Hijacking
```

This demonstrates why session identifiers should be protected both through encrypted communication and appropriate cookie security controls.

---

## 🔄 Replay Vulnerability

The lab also demonstrated a replay-related security weakness.

Previously captured requests may present a security risk when an application does not provide sufficient protection against request reuse.

This exercise demonstrated the relationship between:

**Packet Capture → Request Analysis → Replay Risk**

## 📂 Directory Discovery

**Gobuster** was used to investigate hidden directories and resources exposed by the web application.

Directory discovery can reveal endpoints or resources that may not be directly linked through the application's visible interface.

```text
Web Application
       ↓
   Gobuster
       ↓
Directory Enumeration
       ↓
Hidden Resources
```

## 🚨 Key Security Findings

| Finding | Risk |
|---|---|
| 🔴 **Plaintext Credentials** | Authentication information can be exposed through unencrypted traffic |
| 🔴 **No HTTPS Encryption** | Network communication can potentially be inspected |
| 🟠 **Exposed Session Tokens** | May increase the risk of session hijacking |
| 🟠 **Replay Risk** | Captured requests may potentially be reused |
| 🟡 **Hidden Directories** | Undisclosed resources may increase the application's attack surface |

---

## 🔐 Security Recommendations

Based on the identified weaknesses, important defensive measures include:

- Enforce **HTTPS/TLS** for all application communication
- Never transmit credentials through unencrypted HTTP
- Protect session identifiers
- Apply secure session-management controls
- Configure cookies with appropriate security attributes
- Reduce unnecessary exposure of application directories and resources
- Apply secure server and application configuration
- Monitor network traffic for suspicious behavior
